# fooyin-plugin-2sf

Native Nintendo DS 2SF / MINI2SF input plugin for [fooyin](https://github.com/fooyin/fooyin).
It uses the Vio2SF emulator core and PSFLib from Kodi's `audiodecoder.2sf` addon.

## Features

- Plays `.2sf` and `.mini2sf` directly, without temporary WAV conversion.
- Resolves `_lib`, `_lib2`, etc. dependencies through PSFLib, including companion `.2sflib` files.
- Reads PSF tags such as title, artist, game, year, length and fade.
- Native 44.1 kHz stereo decode, seek support and configurable Vio2SF interpolation quality.
- Fooyin Repeat One is designed to be gapless: the emulated DS audio engine is left running, so an in-game music loop is not restarted and its loop state is preserved. In repeat mode, PSF `length`/`fade` are not used to stop/fade the stream. This behavior still needs testing against real-world 2SF rips.
- Normal playback honours PSF `length` and `fade` tags. If `length` is absent, it uses a 170 s + 10 s fallback; an explicit `length` with no `fade` is played without an added fade.

## Build

This plugin is built against the fooyin SDK. The GitHub Actions workflow downloads the Linux x86_64 SDK and produces both a `.fyplugin` installer bundle and a raw `.so` build artifact.

## Install

Download `fooyin-2sf-linux-x64.fyplugin` from [GitHub Actions artifacts](https://github.com/negr666omg/2sf-fooyin-ai/actions) or from [Releases](https://github.com/negr666omg/2sf-fooyin-ai/releases), then install it from fooyin's Plugins settings page. The raw `.so` is provided for manual installs.

## Notes on 2SF looping

2SF does not expose a universal decoded-audio loop-point table like many streamed game-audio formats. The music is generated by emulating the Nintendo DS sound hardware and game code; the game code itself generally performs the musical loop. This plugin therefore implements Repeat One by continuing the same emulator instance indefinitely rather than stopping at `length`, seeking to zero, or opening a second decoder. That avoids an artificial gap and preserves the emulator's live loop state. A rip that does not actually loop internally will continue whatever the game code produces after its tagged playback duration.
